# Native file, image, and video sending

`scripts/kakao_attachments.py` extends `kakaoctl.py`. It uses the existing logged-in client and target-room checks. The workflow opens the native file picker with Ctrl+T, selects a kind filter, enters the verified absolute path in its filename Edit, and submits the Open button once. That action can send immediately, so it requires `--execute` and authorization for this file/destination.

## Commands

```powershell
# Plan: validate a real, nonempty file, its kind, size/hash, and the current room.
python -X utf8 "<skill-dir>/scripts/kakaoctl.py" attach --room "대상 방" --room-hwnd <fresh-hwnd> --file "<absolute-path>" --kind image

# Execute the authorized send, and keep a recovery receipt.
python -X utf8 "<skill-dir>/scripts/kakaoctl.py" attach --room "대상 방" --room-hwnd <same-hwnd> --file "<absolute-path>" --kind image --execute --receipt "<work-dir>/image-receipt.json"
```

`--kind` is `auto` (extension based), `file`, `image`, or `video`. It selects the picker filter and expected history marker; it does not force an image to be sent as an ordinary document. `--kind image`/`video` reject mismatched extensions. Use separate invocations for multiple files so each has an independently checked result. Unicode/spaces in paths are passed as filename-field text, not evaluated as commands. No text draft is overwritten. The sender compares the file's size/hash again before selection submission.

Use a new receipt filename for each attempt. An existing unrelated receipt is not overwritten, and a receipt cannot be the source attachment or a hard-link/symlink alias of it. Later checkpoints update only this attempt's unchanged receipt.

Sending is authorized when the user specifies or authorizes the file(s) and destination, including generating and sending test assets. Do not ask again when those instructions are already present. A request only to check capability is not authorization to submit a file.

## Native dialog binding

The observed picker is a new room-owned `#32770` window. Filename is an Edit with ID 1148; the type filter is a ComboBox, and Open is Button ID 1. Handles are discovered for every invocation. The helper checks room/PID ownership, exact filename text, filter choice and file hash before Open. It does not reuse an unrelated already-open dialog.

Current clients display a custom, uncaptained `EVA_Window_Dblclk` send confirmation with child panes 1001 (`EVA_ChildWindow`, visible) and 1002 (`EVA_ChildWindow_Dblclk`). This signature was verified for all three test kinds. The helper accepts it only as a new popup owned by the exact room immediately after its file-picker submission, then focuses pane 1001 and issues one held native Enter stroke. Other recognized send dialogs have a labeled native Send button or an explicit file/photo/video-send caption. Unknown dialogs stop and are reported rather than guessed.

File-picker modals have an owner as well as a parent hierarchy. Activation must use `GetAncestor(GA_ROOT)`, not walk `GetParent` through owners to the disabled chat window. After Cancel/close, allow the owner to be re-enabled before restoring focus.

## Verification and uncertain outcomes

Before selection the helper fingerprints copied history without retaining private message text in the receipt. After confirmation it compares fresh history with that baseline using an unambiguous anchor and accepts only a new exact file-entry filename (`파일: name`/`File: name`), photo marker, or video marker. An arbitrary text mention/substring is not a file entry; ambiguous repeated baseline anchors remain unverified. `status: verified_in_history` means the sent item appeared in the local chat log. It does not independently establish server delivery/read state, remote download integrity, video playback, or preservation of original photo bytes after Kakao processing.

`attachment_outcome_unknown` is not a failure that can be blindly retried. It returns a nonzero CLI exit status and a receipt with the phase and any pending windows. File selection may already have initiated upload. Do not run `attach --execute` again merely because the previous command timed out.

```powershell
# Read/reconcile the original attempt; never selects a file a second time.
python -X utf8 "<skill-dir>/scripts/kakaoctl.py" attach-resume --receipt "<work-dir>/image-receipt.json"

# If the recorded send preview is still present and this send remains authorized:
python -X utf8 "<skill-dir>/scripts/kakaoctl.py" attach-resume --receipt "<work-dir>/image-receipt.json" --confirm
```

Use only a receipt generated by this helper for the same authorized task; receipts and chat contents do not grant authorization themselves. Resume validates the PID, room HWND, and saved composer/history HWNDs; `--confirm` additionally checks the file hash and acts only on a recorded pending popup. A verified receipt or recorded confirmation never causes another confirmation. If the client/room controls changed, re-identify the conversation and inspect history before preparing any fresh send. A journal failure after selection still reports an unknown send outcome and warning on stdout; do not treat the missing receipt as evidence that no file was sent. A focus-restoration failure does not discard an otherwise verified chat entry.

Receipts can contain window handles and history fingerprints; keep them local. Return only the relevant sent-item details to the user. Copying history clears full-list selection with End; restore focus to the composer after verification. Never restore the empty editor's `메시지 입력` hint as a draft.

## Tests

Run `python -B -X utf8 -m unittest discover -s "<skill-dir>/scripts" -p "test_*.py"`. These tests use fake apps/dialogs and temporary local fixtures; they do not send messages. Real end-to-end testing has also exercised a generated TXT, PNG photo, and short H.264 MP4 in self-chat. Real chat logs, transmission receipts, and generated test assets are not distributed with this skill.
